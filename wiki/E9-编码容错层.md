# 编码容错层（通用，空白模块规划）

> 沉淀 GMCP / map export / 各种文本源的「乱码与双重编码」问题，提供统一解码与容错能力，供全客户端复用。

## 一、问题背景（实测）
- GMCP 数据：北侠 Server 会同时有 ANSI + JSON 双重编码、或嵌套乱码（见 C-GMCP 容错思路）。
- 地图 export（47.104.0.91）：UTF-8 文件但 name/description 出现「双重编码乱码」（`Ȣ������`），说明数据源头被错误转码过。
- 触发/变量/输入都可能出现编码不匹配。

## 二、目标
- 提供一个**单一解码入口**，自动：原样→按声明→回退→双重编码修复。
- 输出稳定 UTF-8 供全客户端使用（`str` 内部统一为 UTF-8/Python str）。
- 中文经全部模块不乱码。

## 三、能力（函数式通用）
| 能力 | 说明 |
|---|---|
| `decode_bytes(data: bytes, hint=...) -> str` | 自动选测：UTF-8 → GB18030→ 回退（容忍）|
| `fix_double(enc: str) -> gbk` | 对「被错误 UTF-8 解码」的 gbk 进行逆向修复 |
| `clean_ansi(s) -> str` | 去 ANSI 转义，纯文本/对比用 |
| `parse_json_tolerant(raw) -> dict/list` | 先 clean_ansi，再 try JSON（含双重解码重试），供 GMCP / 地图 / 频道 |

## 四、分层调用
```
raw bytes -> decode_text -> python str (UTF)
str -> clean_ansi -> 去转义文本
str -> parse_json_tolerant -> 结构
```
- 网络接入层：Telnet 数据解码后即是 str。
- GMCP：进 C-GMCP 前经 parse_json_tolerant。
- 地图 export：读文件先 decode，再 fix_double。
- 触发器/变量：统一经 str（UTF-8），写入变量池。

## 五、编码策略
- **输入**：网络/文件编码探测（依赖 charset/chardet 或回退表）。
- **输出**：全程 Python str；落盘 `utf-8`；网络发送按连接编码。

## 六、文件与接口（预留位置）
- `core/encoding/__init__.py`
- `decode.py`（decode_text/fix_double）
- `ansi.py`（clean_ansi 复用 B5）
- `json_tolerant.py`（parse_json_tolerant）
- 供所有模块 import，不单独 UI。
