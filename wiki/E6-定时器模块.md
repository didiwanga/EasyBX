# 定时器模块（完整调度中心）

> 统一调度中心：支持周期重复 / 固定时刻(每天) / 日历特定日期 / 星期规则，多种触发动作可组合，并与触发器/宏/脚本双向联动。
> 极端精简不搞 MapReduce 式复杂，但作为「调度中心」设计齐全、可扩展。

## 一、设计原则
1. **统一调度概念**：所有定时器共用 `TimerDef`（触发规则 + 动作序列 + 启停状态），不按类型拆散三个引擎。
2. **挂起线程安全**：单主线程 + 事件总线驱动，绝不阻塞。
3. **双向联动**：定时器可启动/停止「其他自动化」（触发器组、宏、脚本、其他定时器）；反之触发器动作可下拉选择「启动某定时器」。
4. **持久化**：JSON 存 `%APPDATA%\XkxClient\config\timers.json`（统一存储见 E8-配置管理）。
5. **贵精不贵多**：虽为调度中心，仍向玩家暴露精简、清晰的编辑窗。

## 二、TimerDef 数据结构
```text
名称 name           唯一，显示名
描述 description      
触发规则 schedule:
  type:  interval|daily|weekly|once    # 触发类型
  interval_ms: int                    # type=interval 间隔(毫秒)，全项目统一毫秒(见 B3b)
  daily_times: ["HH:MM", ...]         # type=daily 每天固定点(可多个)
  week_days: [1..7]                   # type=weekly 周几
  daily_at: ["HH:MM"]                 # type=weekly 当天时刻
  at: "YYYY-MM-DD HH:MM"              # type=once(一次性)
动作序列 actions: [ActionItem...]     # 按顺序执行
启停: enabled(bool) / running(状态运行时单独看)
上次/下次触发: last_at(s)/next_at(s)   # 运行时显示
```

## 三、触发类型（支持）
| type | 含义 | 示例 |
|---|---|---|
| interval | 每隔 N 毫秒重复 | 每 30000ms 发一次 |
| daily | 每天固定时刻（可多点） | 每天 12:00 / 22:00 |
| weekly | 每周指定星期几的时刻 | 周一/周六 09:00 |
| once（一次性）| 到某绝对时刻执行一次后自动停 | 3 分钟后停止 或 明早 8 点 |

多类型通过 `TimerDef.trigger.type` 区分；同一定时器从列表编辑一次确定，不交叉混淆。

## 四、动作类型（可多，按序执行）
| 类型 | 字段说明 | 说明 |
|---|---|---|
| cmd | `commands: ["cmd1","cmd2"]` | 按顺序发送命令；文本带 `{变量}` 会经变量池替换 |
| script | `name: 脚本名` 或 `code: 源码` | 调用 Lua 脚本/函数 |
| notify | `title,message` | 弹提醒/托盘通知（不操作游戏） |
| control | `target: 自动化名称, op: start/stop/pause/resume` | 控制触发器/宏/脚本/其他定时器启停 |
| wait | `delay_ms` | 动作序列内插入延时（毫秒，配合等待） |

> 动作序列与 B3b 宏的步骤模型保持「同一套动作器」，避免两套执行逻辑，减少返工。

## 五、调度中心（TimerEngine → Scheduler）
- **底层**：单一 `QTimer(1000ms)` 每秒 tick 检查：
  - daily/weekly/once → 到达 when 触发；
  - interval → 独立 `QTimer` 或 tick 计数对账触发。
- **与自动化总线交互**：动作执行复用「事件总线 + 发送回调 + 变量池」；
  - 文本命令走 `send_command`（与触发器/宏同一条发送管道）。
  - `{变量}` 与脚本 Lua 变量同源（见 B3c/B3b 变量池）。

- **调度接口**：
  - `register(def)` / `unregister(name)` / `clear()`
  - `start(name)` / `stop(name)` / `stop_all()` → 改 enabled
  - `is_running(name)` / `next_at(name)` / `last_at(name)`
  - `list_all()` -> [TimerDef]
  - 持久化 `load()/save()`

## 六、与触发器/宏/脚本联动（重点）
**触发器动作「启动定时器」下拉**（用户指定，来自旧需求）：
- 在触发器编辑器中，动作类型新增「启动定时器」，右侧下拉框列出**已添加的定时器名**，运行时用户可把触发器动作为「触发时启动某定时器」。
- 这样：触发器（例如遇到说话）→ 启动定时器（开始轮询）→ 定时到点做动作。
- 同理支持 `停止定时器` 动作（同一下拉）。

**定时器动作可反过来控制其他自动化**：触发时执行 `control` 动作，起停触发器/宏/脚本/其它定时器（同一引擎统一）。

## 七、对话框（TimerDialog / 列表）
- 新增/编辑：名称、描述、触发规则（类型+时间/间隔/星期日历）、动作序列（多步）、enabled。
- 列表：名称/类型/间隔或时间/启用/A、上/下次触发。
- 每次操作实时 save。

## 八、编码/文件
- 存 JSON `%APPDATA%\XkxClient\config\timers.json`（UTF-8），与别名/触发器同文件命名规范。
