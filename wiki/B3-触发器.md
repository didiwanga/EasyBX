# B3 触发器（定稿 v2 — 含模板捕获 / 变量 / 多条件 / 延时）

> 覆盖旧项目候选 4「触发器模板捕获」。宏中的「触发器步骤」复用本设计（见宏）。

## 触发器模型
每条触发器：
| 字段 | 说明 |
|------|------|
| 启用 | 是否参与匹配 |
| 名称 | 标识 |
| 匹配类型 | 包含 / 正则 / 精确 / 模板 |
| 条件 | 一个或多个（默认 1 个），见「多条件」 |
| 延时 | 命中后延时多少毫秒执行动作，默认 0 立即执行 |
| 动作 | 命中后执行的一个或多个动作（见「动作」） |

## 动作（Action，多个按序执行）
- 触发器命中后可执行多条动作，与宏步骤/定时器动作共用「同一套动作器」（见 B3b/E6），避免两套执行逻辑。
- 动作类型：
  | 类型 | 说明 |
  |------|------|
  | 输出命令 | 发送命令，可含 `{变量}` 代入 + `;` 拆分多命令 |
  | 启动定时器 | 下拉选择已添加的定时器名，命中即启动 |
  | 停止定时器 | 下拉选择定时器名，命中即停止 |
  | 通知 | 弹提醒/托盘通知（不操作游戏） |
  | 控制 | `target: 自动化名称, op: start/stop/pause/resume`（控制触发器/宏/脚本/其它定时器）|

## 模板捕获（template 类型）
- 模板 = 带 `{变量名}` 占位符的固定文本，命中时把对应段字符捕获到**全局变量**。
  例：`童百熊说到：你现在应该去{地点}找药童买一些药材` → 命中后「地点」变量 = 实际地名。
- **统一格式**：捕获用 `{变量名}`，调用也用 `{变量名}`（**弃用旧项目 `$变量名` 风格**）。编号/命名都支持：
  - 命名：`{地点}`
  - 编号：`{v01}`
- **变量创建方式**：通过「触发器命中」或「宏中的触发器步骤」创建。

### 颜色属性（{名:color}）
- 占位符可带颜色：`{v01:color}`。
- 命中时该字段是**二维**：既捕获字符，也捕获颜色信息。
  - 变量本体 = 字符（`{v01}` 取字符串）
  - `.color` 部分 = 颜色，以 `#000000`–`#FFFFFF` 十六进制存入。
    例命中 `...去{v01:color}找...`，服务器发的"长安"是红色 → v01 内部存 `{长安,#FF0000}`。
- **调用**：
  - `{v01}` → 取字符 → `say {v01}` 发 `say 长安`
  - `{v01:color}` → 取颜色 → `say {v01:color}` 发 `say #FF0000`
- 颜色统一转换/存储为 16 进制 `#RRGGBB`。

## 全局变量域
- 捕获到的变量**全局可用**，可在以下位置调用 `{变量名}` 代入：
  - 命令输入框直接发送
  - 定时器发送的命令
  - 宏的命令步骤 / 判断步骤
  - 本触发器的输出命令
- 变量是客户端运行时的全局数据，**仅运行期内存，不持久化**（退出客户端即清除）。

## 多条件
- 每条触发器默认 1 个条件；点「➕」可添加多个条件。
- 条件之间关系：**全与 (and) 或 全或 (or)**，**默认或 (or)**。

## 延时执行
- 命中后延时指定毫秒再执行动作；默认 0 立即执行（全项目时间统一毫秒，见 B3b）。

## 计数器
- 每条触发器记录命中次数（可显示/可清零），用于统计与条件判断（如「命中第 N 次才执行」）。
- 计数仅运行期内存，不持久化；触发器编辑器提供计数查看与重置。

## 宏中的触发器步骤
- 宏的「触发器步骤」复用本设计（模板捕获/变量/多条件/延时一致），不在宏处重复阐述。
- **一个触发条件可同时获取多个变量**（以条件中写的变量数量为准）。
- **多条件赋值**：条件多个时按与/或关系——
  - 与：各条件中的变量**都**赋值；
  - 或：仅有唯一命中的条件中的变量赋值。

## 验收
- [ ] template 匹配：命名 + 编号占位符均可捕获
- [ ] 颜色变量 `{v01:color}` 存 `#RRGGBB`；`{v01}` 取字、`{v01:color}` 取色
- [ ] 变量全局可用：命令框 / 定时器 / 宏 / 触发输出均可 `{变量}` 代入
- [ ] 多条件 + / 或 关系正确（默认或）
- [ ] 延时执行（默认 0）正确
- [ ] 动作（输出命令 / 启动停止定时器 / 通知 / 控制）按序执行
- [ ] 计数器命中计数正确、可查看与重置
- [ ] 宏触发器步骤复用本设计
