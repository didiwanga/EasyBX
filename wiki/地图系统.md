# 地图系统（新客户端定稿 v2）

> 旧项目仅作「功能目标」参考，**不沿用其设计/源码**，尤其本地地图绘制完全不采用旧版方案。
> 服务端（47.104.0.91/api/map/，v2 协议）实测可用，作为采集与路径后端。

## 架构全景
```
pkuxkx --GMCP.Move--> [MapSync: 采集上报] --POST /api/map/moves--> map_server(sqlite)
                                                    │
pkuxkx --look--> [LookCapture: 房间细节]             │ GET /export + /areas?full=1
                                                    ▼
                        [MapCache: 拉取+本地缓存 %APPDATA%\XkxClient\config\map_cache.json] (启动500ms + 60s周期)
                                                    │
                          ┌───────────────┬─────────┴────────┬──────────────┐
                          ▼               ▼                  ▼              ▼
                  房间拓扑画布      区域拓扑画布          世界静态图       [Navi: 寻路+walk]
```

## 一、数据采集
### MapSync（本地采集上报）
- 订阅 `GMCP.Move`：`result=true` 时从 `short`+`dir` 生成 room+边；`result=false`(撞墙)不更新。
- 监听用户发出的方向命令记 `_pending_dir`（短名规范化）。
- 悬空出口（look 见但未走）入 dirty。
- 15s 周期批量 `POST /api/map/moves`；掉线≤15s 数据；防重入。

### LookCapture（房间细节）
- 移动到未记录房间 / 用户右键**手动**触发 look（不自动刷屏）。
- 解析 description + objects（NPC/玩家/物品/可交互物，格式见 B 文档 look 解析层）。
- 结果入本地 + 上报。

### MapCache（拉取+缓存）
- 启动 500ms + 60s 周期 `GET /api/map/export` + `/areas?full=1`。
- 写本地 `%APPDATA%\XkxClient\config\map_cache.json`，离线可看。
- **布局坐标回写**：客户端布局后把 `pos_x/pos_y` 传回服务端，使 route 的 distance 有效。

### 编码
- 全程 UTF-8（服务端 make_room_id 用 name.encode('utf-8')）；中文必须正确，杜绝乱码。
- 解析容错：JSON 双重编码 + ANSI 清洗（复用 C/GMCP 容错思路）。

## 二、导航（重点：真正可走、接入自动化）
### 路径来源（本地优先 + 服务端补充）
1. 本地 BFS：用本地拓扑（MapCache.edges）先算。
2. 本地不足/无路 → 服务端 `GET /api/map/route?from=<rid>&to=<rid>`。
3. 都无路 → 提示无路，不盲走。

### 自动 walk（新功能，旧版只画不走）
- 得到方向序列 → 转命令 → **逐条发送**。
- 步进节奏**可配置**，默认 ~1.5s/步（范围 0.8~3s 可调）。
- **每步等 GMCP.Move 确认**：`result=false` 立即停下 + 报错；连续超时也停。
- 交互：停止/暂停按钮可见；当前步高亮。

### 导航接入自动化
- 导航状态事件（开始 / 每步 / 到达 / 卡住 / 停止）入事件总线，供触发器/宏订阅。
- **到达目标可触发命令序列**（配置目标点 → 到达后发初始化命令）。

### 边界
- 特殊方向 enter/out/up/down/nu..wd 纳入方向集与反向表。
- 单向边（只有去没有回）在地图标示，walk 遇单向门单向按路径走。

## 三、呈现（重点改进，不沿用旧版）
### 本地房间拓扑 <--> 矢量交互画布（QGraphicsScene）
- 节点=房间，边=方向连线。
- **交互**：滚轮缩放 / 拖拽平移 / 节点点击查看信息(名称/描述/NPC/出口) / 搜索框定位。
- **布局**：方向感知 BFS（8 方位 + 上下），同方向并列不重叠，冲突螺旋避让；单向边短画暗色、垂直方向虚线；玩家当前位置高亮（金环）。
- 质量：保持格子对齐，避免旧版乱象。

### 区域拓扑 <--> 矢量画布
- 力导向布局；区域节点=区域，跨区域寻路高亮；双击节点选目标。
- 数据 /areas?full=1 的 area_edges。

### 世界静态图
- worldmap.png，等比缩放，滚轮缩放/拖动/重置（R 已规划）。叠加区域/城市占位标记（可选）。

## 四、特殊房间 / NPC / 区域
- **特殊房识别**：马车行/渡口等，靠映射服务器数据或 look 描述关键词，标注类型（如「马车行」可跨城、「渡口」可渡河）。
- **NPC 查询**：服务端 `/api/map/npcs?name=` + 本地 look objects 检索。
- **区域归类**：服务端 /areas?full=1 权威 + localmaps 文本辅助。

## 五、模块划分（新文件，不沿用旧代码）
- `core/map/`：map_sync / map_cache / look_capture / navigate
- `ui/map/`：local_map_widget（矢量）、world_map_widget、world_image
- 服务端活着为存储后端；本地解析逻辑从零实现。
