# 启动流程（基础件其五）

> 入口与初始化顺序：从 `main` 到主窗口显示，确保各引擎/配置/资源就绪且可安全退出。

## 一、入口（main.py）
```
1. QApplication 创建
2. 全局 QSS 应用（B9/_build_global_qss）
3. 设置应用图标 app.ico（R）
4. 解析命令行（可选：直接连接某服务器/加载脚本）
5. 创建 XkxApp(核心) + 主窗口 + 装配（见下）
6. 启动事件循环 exec()
7. 退出清理（保存配置/断开连接/停所有自动化）
```

## 二、装配顺序（无依赖先行）
```
ConfigManager 单例
    → 加载全局 config.json + layout.json
EventBus（全局唯一总线）
    → 挂 verbose 日志（可选）
资源 R（app.ico/worldmap.png/字体）
编码容错层（E9）就绪
各 Engine（可延迟到账号连接时实例化）：
    - 触发器/别名/定时器/宏/脚本（默认空，账号连接时按账号加载）
    - GMCP 路由、look 解析、地图同步（挂总线）
主窗口 MainWindow（menuBar+toolbar+QTabWidget+Dock+statusbar）
    → 恢复 dock 布局（layout.json）
登录窗 D3（启动先登录窗，或直接显示主窗）
```

## 三、登录/连接流程（D3 + D4）
- 启动 → 登录窗（或主窗空态）→ 选择账号 → 新建标签（D4）→ 连接（A1）→
  GMCP 订阅（C）→ 自动登录（D 固定算法+编码）→ 配置化初始化命令 → 状态开始推。

## 四、退出清理
- 保存所有配置（ConfigManager.save）
- 断开所有连接、停所有自动化（宏/脚本/定时器）
- 关闭托盘/窗口
- 保证无残留线程

## 五、异常兜底
- 启动中任一步失败 → 提示但不崩溃；可重试连接。
- 清理异常吞掉但记日志。

## 验收
- [ ] main→装配→登录窗→主窗 顺序正确
- [ ] 全局配置/资源/总线就绪后再建窗口
- [ ] 多账号按需实例化（不预载全部）
- [ ] 退出安全（保存+断开+停自动化）
- [ ] 异常不崩溃可重试
